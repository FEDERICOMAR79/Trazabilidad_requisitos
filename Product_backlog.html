HU-01
Registrar y actualizar tripulantes

Como PersonalAdministrativo quiero registrar y actualizar los datos de los tripulantes (pilotos y copilotos) para mantener el personal disponible y correctamente identificado en el sistema.

Criterios de aceptación

  • Dado un tripulante nuevo con todos los datos obligatorios (nombre, identificación, rol, licencia), cuando el administrativo lo guarda, entonces queda disponible en el listado de tripulantes.
  • Dado un tripulante existente, cuando se editan sus datos, entonces el sistema actualiza la información y conserva la fecha del último cambio.
  • Dado que falta un campo obligatorio, cuando se intenta guardar, entonces el sistema rechaza el registro e indica el campo faltante.

HU-02
Registrar y actualizar tripulaciones

Como PersonalAdministrativo quiero registrar y actualizar tripulaciones (parejas piloto-copiloto) para tenerlas disponibles al momento de asignarlas a un vuelo.

Criterios de aceptación

  • Dado un piloto y un copiloto activos y certificados, cuando el administrativo los agrupa, entonces el sistema crea la tripulación y la deja disponible para asignación.
  • Dado que falta el piloto o el copiloto, cuando se intenta guardar, entonces el sistema no permite crear la tripulación y notifica el requisito faltante.
 Historia de usuarioAlta
HU-03
Registrar y actualizar vuelos

Como PersonalAdministrativo quiero registrar y actualizar los datos de cada vuelo (fecha, origen, destino, condiciones meteorológicas y de visibilidad previstas) para que operadores y tripulación cuenten con información confiable.

Criterios de aceptación

  • Dado un vuelo nuevo, cuando se ingresan fecha, origen, destino, condiciones meteorológicas y visibilidad previstas, entonces el sistema lo guarda y lo hace consultable.
  • Dado un vuelo existente, cuando se actualizan sus condiciones previstas, entonces el sistema conserva un registro de la actualización con fecha y hora.
 Historia de usuarioAlta

HU-06
Registrar resultado de simulación

Como Piloto quiero que el resultado numérico de mi simulación en un escenario quede registrado en el sistema para que se use en las decisiones de asignación.

Criterios de aceptación

  • Dado un piloto que completó una simulación, cuando se registra el resultado numérico, entonces queda asociado al piloto, al escenario y a la fecha de realización.
  • Dado que ya existe un resultado vigente del piloto para ese escenario en el año en curso, cuando se registra uno nuevo, entonces el sistema lo marca como vigente y conserva el anterior en el histórico.

HU-07
Recomendar tripulación según escenario más aproximado

Como OperadorVuelo quiero que el sistema identifique el escenario estandarizado más aproximado a un vuelo y me recomiende la tripulación con mayor puntuación en ese escenario para asignar la tripulación más adecuada.

Criterios de aceptación

  • Dado un vuelo con condiciones meteorológicas y de visibilidad definidas, cuando el operador solicita una recomendación, entonces el sistema identifica el escenario más próximo y lista los pilotos disponibles ordenados por puntuación descendente.
  • Dado que ningún piloto disponible tiene puntuación vigente en ese escenario, entonces el sistema lo advierte explícitamente en vez de mostrar una recomendación vacía.
 Historia de usuarioAlta
HU-08
Asignar tripulación a un vuelo

Como OperadorVuelo quiero asignar la tripulación a un vuelo (confirmando o ajustando la recomendación, con motivo si me aparto de ella) para dejar formalizada la decisión.

Criterios de aceptación

  • Dado que el operador confirma la tripulación recomendada, cuando registra la asignación, entonces el sistema la vincula al vuelo y la marca como asignada.
  • Dado que el operador asigna una tripulación distinta a la recomendada, cuando confirma, entonces el sistema exige un motivo y lo guarda junto con la asignación.
 Historia de usuarioAlta
